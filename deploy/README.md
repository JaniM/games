# Deploying to games.seequ.dev

One NixOS server runs everything: Postgres, the backend, and Caddy, which serves the frontend and proxies `/api` (WebSockets included) to the backend.

The server doesn't run NixOS yet, so there are two steps, each with its own tool:

1. **[nixos-anywhere](https://github.com/nix-community/nixos-anywhere)** installs NixOS over SSH, once. It wipes the disk and installs `nixosConfigurations.bootstrap`: a system that boots and accepts your SSH key, without the site.
2. **[Colmena](https://colmena.cli.rs)** deploys the full system, now and for every later change.

The site is left out of the bootstrap on purpose. The installer keeps its filesystem in RAM, and compiling the backend and frontend there could run a small server out of memory. Colmena builds them on the installed system's disk.

| File | What |
|---|---|
| `default.nix` | The two outputs: `nixosConfigurations.bootstrap` and `colmena` |
| `games.nix` | The site: Postgres, the backend service, Caddy, the firewall |
| `host.nix` | The machine: boot loader, SSH key, state version |
| `disk.nix` | The disk layout (disko). **Erases `/dev/vda`** |
| `backend.nix`, `frontend.nix` | The two packages |
| `hardware-configuration.nix` | Generated by nixos-anywhere. Not in git until the install has run |

Postgres listens on its Unix socket only. The backend connects as the Unix user `games`, which Postgres maps to the role `games` (peer authentication), so there are no passwords or secrets to manage. The backend runs its own migrations on startup.

## Wire it into the flake

`flake.nix` needs the `disko` input, the outputs, and the two tools in the dev shell. Apply the patch from the chat, or make these four changes:

```nix
inputs = {
  # …
  disko.url = "github:nix-community/disko";
  disko.inputs.nixpkgs.follows = "nixpkgs";
};

outputs = { self, nixpkgs, flake-utils, llm-agents, disko, ... }:
  flake-utils.lib.eachDefaultSystem (system: /* … as now … */)
  // import ./deploy { inherit nixpkgs disko; };
```

```nix
devShells.default = pkgs.mkShellNoCC {
  packages = projectTools ++ [ jailed-claude pkgs.colmena pkgs.nixos-anywhere ];
```

Then run `nix flake lock` to pin `disko`.

## Before the install

- **The server** must be x86_64 Linux that you can `ssh root@<ip>` into, with kexec support (nearly all are) and at least 1 GB of RAM, more is safer. If it isn't `root`, the user needs passwordless sudo. This is a small VPS-style server; for another architecture, see `system` in `default.nix`.
- **Everything on its disk is erased.** Run `lsblk` on the server and check that `/dev/vda` in `disk.nix` is the disk to install on.
- **Your SSH public key** goes into `host.nix`. It is the only way in afterwards, and evaluation fails until it is there.
- **DNS.** Point `games.seequ.dev` (A, and AAAA if the server has IPv6) at the server. Caddy asks Let's Encrypt for a certificate on its own, which needs that name and ports 80 and 443.
- The installed system gets its network from DHCP, which is what VPS providers usually give. If yours hands out a static address, set it in `host.nix` too, or the server won't come back after the reboot.

## Install NixOS

From the repo root, in `nix develop`:

```bash
nixos-anywhere \
  --flake .#bootstrap \
  --generate-hardware-config nixos-generate-config deploy/hardware-configuration.nix \
  --build-on remote \
  --target-host root@<ip>
```

It kexecs into an installer, partitions the disk, installs, and reboots. `--build-on remote` is for the Mac, which can't build Linux packages; the bootstrap is nearly all downloaded from the binary cache. Afterwards:

```bash
ssh-keygen -R <ip>          # the server has new host keys
ssh root@<ip>               # should work with your key
```

**Commit `deploy/hardware-configuration.nix`.** nixos-anywhere ran `git add --intent-to-add` on it so the flake could see it, but the system you just installed depends on its contents. It contains no secrets.

## Deploy the site

1. **The npm hash.** `frontend.nix` has `lib.fakeHash`. Run `colmena apply --on games`; it builds on the server and fails on the frontend's pnpm dependencies with `got: sha256-…`. Put that hash in `frontend.nix` and run it again. Repeat whenever `frontend/pnpm-lock.yaml` changes.
2. `colmena apply --on games` builds the backend and frontend on the server and switches to them.

From then on, every change is `colmena apply`. The Rust build needs a few GB of memory; on a small server, add swap.

## Running it

```bash
ssh root@games.seequ.dev
journalctl -u games-backend -f
systemctl status caddy postgresql
sudo -u postgres psql games
```

A deploy that changes the backend restarts it and drops open game sockets; clients reconnect.

Nothing backs up the database. Before there are users you'd miss, add `services.postgresqlBackup` and copy the dumps off the machine.

## Reinstalling

`nixos-anywhere --flake .#bootstrap …` wipes the disk again, database included. For normal changes use `colmena apply`, never the installer.
